## 1. 트레이스 구조 — Transaction / Span / SpanEvent

**택배 비유**로 보면 한눈에 들어온다.

| 개념 | 택배 비유 | 실제 의미 | 생성 단위 |
|---|---|---|---|
| **Transaction** | 택배 주문 1건 | 요청 전체를 묶는 단위 | **요청당 1개** |
| **Span** | 물류센터 한 곳에서 찍은 도장 | Agent가 붙은 서버 1대를 거친 기록 | 거쳐간 **서버(노드) 수만큼** |
| **SpanEvent** | 그 센터 안에서 실제로 한 작업들 | 서버 안에서의 메서드 호출 | **메서드 호출 1개마다** |

- 하나의 Transaction이 여러 센터(서버)를 거치며 **Span**을 찍고, 각 Span 안에 **SpanEvent**들이 담기는 구조.

### 1-1. 흐름 예시 `[브라우저] → [Frontend] → [Backend] → [MySQL]`
1. 요청 1개 생성 → 요청 전체를 묶는 **Transaction ID** 획득
2. 각 서버에 들어오면 그 서버의 **Span ID**와 **부모 Span ID**를 적음
3. 그 서버에서 메서드를 호출할 때마다 **SpanEvent**를 적음

## 2. 서버 간 Span은 어떻게 이어지나 (가장 중요)

서로 다른 서버의 Span은 **HTTP 헤더에 정보를 실어 보내서** 연결한다.

[🖼️ 원본 이미지: HTTP 헤더로 다음 서버에 Span 정보 전파]

| 헤더 매칭 | 뜻 |
|---|---|
| **nextSpanId ↔ spanId** | 앞 서버가 "다음 스팬 번호"를 알려주면, 다음 Agent 노드 서버가 **그 값을 자기 Span ID로** 사용 |
| **destinationId ↔ acceptorHost** | 스팬 A의 **목적지 ID**와 스팬 B의 **수신 호스트**가 일치해야 **서버 맵에 선이 그어짐** |

[🖼️ 원본 이미지: destinationId↔acceptorHost 일치로 서버 맵에 선 연결]

> 🔑 즉, **호출한 쪽이 미리 정한 다음 스팬 번호**를 받은 쪽이 그대로 쓰고(체인 연결), **목적지/수신 호스트가 맞아떨어질 때만** 서버 맵 위에 두 노드를 잇는 화살표가 생긴다.

## 3. 플러그인 구성요소

> 📌 **요약** — 플러그인 **JAR 하나**를 Agent·Collector·Web 세 곳에 다 넣는다. `type-provider.yml`은 세 곳 모두 읽지만, **`ProfilerPlugin` 구현체는 Agent만 실제로 쓴다.**

| 구성요소 | 역할 | 비유 |
|---|---|---|
| **`type-provider.yml`** | 플러그인이 제공할 타입(`ServiceType`, `AnnotationKey` 등) 정의 → Agent·Web·Collector에 제공 | **용어 사전** |
| **`ProfilerPlugin` 구현체** | 대상 클래스를 변환해 추적 데이터로 기록하는 구현 클래스 | **작업 지시서** |

- `ProfilerPlugin` 예: 추적하고 싶은 **남의 라이브러리 클래스에 바이트코드를 삽입** → 삽입된 코드가 실행되며 **SpanEvent를 남김**.

## 4. 배포 위치 3곳과 동작 흐름

플러그인 JAR는 **하는 일이 다른 세 곳**에 배포된다.

[🖼️ 원본 이미지: 플러그인 JAR의 3곳 배포 위치]

| 위치 | 하는 일 |
|---|---|
| **Agent** | 데이터를 **만드는 곳** (앱에 붙어서 감시) |
| **Collector** | 데이터를 **받는 곳** (저장 + 집계) |
| **Web** | 데이터를 **보는 곳** (화면으로 그림) |

[🖼️ 원본 이미지: Agent/Collector/Web 각각의 역할]

### 4-1. 시작 시 세 곳 모두 수행하는 공통 절차
1. 자기 **플러그인 디렉터리의 JAR**를 하나씩 순회
2. **`type-provider.yml` 파싱** → `ServiceType`·`AnnotationKey` 등록
3. **`ServiceLoader`로 `ProfilerPlugin` 읽기** → 거기 적힌 클래스를 로드

> ⚠️ 세 곳 다 JAR를 읽고 타입을 등록하지만, **바이트코드를 실제로 변환해 추적을 수행하는 건 Agent뿐**이다. Collector·Web은 같은 "용어 사전"을 공유하려고 JAR를 읽는 것.

## 정리

| 주제 | 핵심 |
|---|---|
| 3계층 | Transaction(요청1개) → Span(서버1대) → SpanEvent(메서드1개) |
| 서버 연결 | HTTP 헤더: nextSpanId↔spanId(체인), destinationId↔acceptorHost(서버맵 선) |
| 플러그인 | JAR 1개 = type-provider.yml(용어 사전) + ProfilerPlugin(작업 지시서) |
| 배포 | Agent(생성)·Collector(저장/집계)·Web(조회) 3곳 |
| 실제 변환 | 바이트코드 변환·추적은 **Agent만** |
