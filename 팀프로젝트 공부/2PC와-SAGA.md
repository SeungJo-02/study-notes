## 2PC
- 2PC : 기본적으로는 DB 프로토콜이다.

### 역할
- 조정자 : 트랜젝션 총괄 역할(서버다)
- 참여자 : 실 데이터를 조작하는 각 DB

### 동작 방식
- 준비
  - 조정자가 모든 참여자(DB)에게 커밋 할 건지 물어봄
  - 참여자는 Lock을 건다
    - 준비 상태에 따라 Y/N로 응답 **(아직 커밋이 아닌 락을 건체로 대기임)**
- 커밋/롤백
  - 모든 참여가가 Yes라면 조정자가 커밋 명령을 내림
  - 아니라면 전부 롤백
  - 두 상황 모두 일어나면 DB들은 락을 푼다

### 장단점
- 장
  - 원자성(Atomicity) 보장
- 단
  - 느리다 : 모든 DB가 Lock을 걸고 기다려야하니까(트래픽이 많아지면 절망)
  - SPOF : 조정자 서버가 죽으면 블로킹(blocking) 상태로 DB들이 Lock을 걸고 대기함<br>(참여자 DB 중 하나가 뻑나도 그게 정상이 될 때까지 문제가 된다)

## SAGA
- 하나의 큰 트랜잭션을 여러 개의 작은 로컬 트랜잭션으로 쪼개서 순서대로 실행하는 패턴
  - 로컬 트랜잭션
    - 하나의 DB 인스턴스 안에서만 일어나는 트랜잭션
    - 속도 빠름, 관리 쉬움, ACID 100%
  - 분산 트랜잭션
    - 2개 이상의 독립적인 DB**나 서비스**에 걸쳐 일어나는 트랜잭션
      - 2PC : 속도 느림, 일관(원자)성 가짐, 자동 롤백
      - Saga: 속도 빠름, 결과적 일관성, 보상 트랜잭션
- 즉,
  - 가능한 분산 트랜잭션을 안 만들게 설계
  - 그래도 여러 서비스에 원자성이 필요하면 사가(대신 보상트랜잭션 로직 리소스 필)

### 보상 트랜잭션
- 보상 트랜잭션 = 이미 커밋된 앞 단계들을 거꾸로 되돌리는 트랜잭션.<br>(2PC는 커밋 전이라 그냥 롤백하면 되지만, 사가는 각자 이미 커밋해버려서 되돌리는 로직을 따로 실행해야 함) 예: 결제↔환불, 재고차감↔복구
